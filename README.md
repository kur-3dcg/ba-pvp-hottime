# 対抗戦ホットタイム

ブルーアーカイブの防御履歴を記録し、相手プレイヤーごとの時間帯を確認するWebツールです。

## GitHub Pagesでの公開

GitHubのリポジトリへソースをアップロードした後、Settings → Pages → Build and deployment → Sourceで「GitHub Actions」を選択します。`main`へのpush、またはActionsの「Publish GitHub Pages」から手動実行すると、ビルドして公開します。公開URLのサブディレクトリとOCRファイルの参照先は自動で合わせます。

`sample/`、ローカルのバックアップJSON、`.env`、`node_modules/`はアップロード対象外です。利用者の記録は引き続きブラウザー内だけに保存されます。ローカル版と公開版は保存先が別なので、記録を移す場合はローカル版でバックアップを保存し、公開版で取り込んでください。

## ローカルでの起動

Node.js 22.12以降（開発時は24）とnpmを使用します。

```sh
npm install
npm run dev
```

ブラウザーで http://127.0.0.1:5173/ を開きます。WindowsのChromeで動作確認しています。記録はアクセス先のオリジンごとのブラウザー保存です。`localhost`と`127.0.0.1`、ポートが違うURLは保存先も異なるため、同じURLを使ってください。

```sh
npm run build
npm run preview
```

配信用ファイルは`dist/`です。サーバー処理はなく、静的ホスティングで動作します。ビルドにはサンプル画像や利用者の記録を含めません。開いている画面から古いハッシュ付きファイルが参照されることを考慮して、ビルドは既存の出力を保持します。配布時は新規チェックアウトでのビルドを推奨します。

## 機能

- 顔アイコンはST・SP共通の名前順です。ホシノ（攻撃／防御）はホシノ（臨戦）に統合し、既存の設定にも適用します。プレイヤー編集でアイコンを選ぶと即時保存され、編集画面を閉じても保持します。
- グラフは記録の変更を即時反映し、サンプル表示中の追加時は実データ表示へ戻ります。選択中の期間・プレイヤーによる絞り込みは維持します。

- プレイヤー一括削除：「プレイヤー」タブから実行できます。赤字の警告付き確認画面で確定後、全プレイヤーの名前・アイコン設定・記録との紐付けを削除します。防御記録は「プレイヤー未設定」として残り、全体グラフにも含まれます。記録編集で再割り当てできます。記録の一括削除とは別の操作です。

- 手入力：0～23時間・0～59分。1時間以上は分を無視します。
- 画像読み取り：複数画像を一括選択・ドロップできます。1枚ずつ防御・攻撃の判定、経過時間、プレイヤー名を確認・修正し、保存すると次の画像を自動で読み取ります。個別のスキップと中止もできます。閉じても保存済みの記録は残ります。
- 基準日時：画像内の日時（EXIF/XMP・PNGテキスト）→ 規定形式のファイル名 → ファイル更新日時 → 読み取り開始時の現在時刻の優先順です。取得元を表示し、確認画面で修正できます。後ろ2つを使う場合は軽い警告を表示します。
- ファイル名の形式：`BlueArchive YYYY-MM-DD HHMMSS[_連番].png`（例：`BlueArchive 2026-10-04 101801_1.png`）。JPEG・WebPにも対応し、日本時間として解釈します。
- グラフ：0〜23時の時間帯別ヒートマップと、1時間単位の棒グラフ。全体・個人・2～10人比較、全期間・7日・30日・90日を切り替えます。
- プレイヤー：顔アイコン、名前の編集、プレイヤー名・生徒名・各言語の別名・よみによる検索。
- プレイヤー統合：名前の変更先が既存プレイヤーと同名なら確認を表示します。「統合する」で両方の記録を保持してまとめ、「統合せず保存」で別人として残せます。統合先の顔アイコンを優先し、未設定なら変更元のものを使います。
- 記録：日時とプレイヤーの編集、確認付き削除、バックアップのダウンロード・取り込み。
- 一括削除：「記録一覧」→「記録を一括削除」。確認画面に消去件数と元に戻せない旨を赤字で表示します。絞り込みにかかわらず全記録を削除し、プレイヤー・アイコン・名前補正辞書・設定は保持します。確認画面から削除前のバックアップを保存できます。
- アイコン：STRIKER/SPECIALの280件を同梱（2026年10月29日更新、ホシノの攻撃・防御は統合済み）。「アイコン一覧を更新」でGoogleスプレッドシートから再取得します。取得失敗や列変更時は従来の一覧を保持します。起動時は同梱一覧とブラウザー保存済み一覧のうち、更新日時が新しいものを使います。

## OCRの実装と精度

記録と画像を端末内で処理するため、当初案のFlask + PaddleOCRに代えて、ブラウザーで動く[Tesseract.js](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)を採用しました。日本語・英語の学習データとWASMは`npm run prepare:ocr`で`public/ocr/`へコピーされます。`dev`と`build`の前に自動実行され、画像やOCRの結果を外部APIへ送信しません。

画像の履歴領域を切り出し、カードの境界から行を作り、行内の固定範囲で時間・名前・攻防を認識します。文字列の検出件数の順番では結合しません。盾アイコンの形状も防御判定の補助に使用します。標準範囲は提供された3840×2160の5枚に合わせた設定です。違うレイアウトは「読み取り範囲」で調整し、設定を保存できます。

サンプル5枚では、上端が切れていない計15行の時間と攻防を確認しました。名前の「芹沢」が「庁沢」などになる誤読が残ります。元画像と名前を必ず照合してください。修正した名前は同じ誤読に対する補正辞書として保存でき、「使い方」からクリアできます。画像の端で欠けた行は除外します。

画像確認画面では「同じ名前にまとめる」が既定です。「匿名」も含め、同名の既存プレイヤーに記録し、未登録なら作成します。同じ画像内の同名行もまとめます。既存の同名プレイヤーが複数いる場合は保存順で最初のものが対象です。別の相手に紐付ける場合はプレイヤーを選び、別人として追加する場合は「新規として個別登録」を選んでください。過去のプレイヤーは自動統合されません。顔アイコンは手動で選択し、画像からのキャラクター自動照合は行いません。

手入力・画像登録では、同じ画像の同じ行、または同じプレイヤーで防御時刻が分単位で一致する記録を重複候補として表示し、追加するか確認します。「使い方」の「重複確認時の初期選択」で追加する／追加しないを設定できます（初期設定は追加しない）。設定はブラウザーに保存され、どちらの設定でも確認画面が出ます。重複以外は通常どおり追加します。同名でも別プレイヤーとして登録した記録は、名前だけでは重複判定しません。別画像で算出時刻が異なる重複は検出できない場合があります。ゲームの「○時間前」「○日前」は概算で、正確な分までは復元しません。バックアップ取り込みの同一ID除外は従来どおりです。

メタデータは[exifr](https://github.com/MikeKovarik/exifr)とPNGテキストの読み取りを使用します。タイムゾーンのない日時はJSTとして扱います。

## 保存と外部通信

`localStorage`にプレイヤー、記録、名前補正、アイコン一覧、読み取り範囲を保存します。元画像・切り出し画像は保存せず、確認画面を閉じると解放します。ブラウザーのデータ削除・別端末への移行にはバックアップを使ってください。

外部通信はアイコン画像の取得、アイコンマスターの更新、Google Fontsの読み込みです。マスター更新にはスプレッドシートの一般閲覧と通信が必要です。APIキーやGoogleログインを要求しません。外部通信が失敗しても記録・グラフ・同梱OCRを利用できます（アイコン画像は代替表示）。

## 確認コマンド

```sh
npm test
npm run build
```

開発サーバーを起動した状態で、インストール済みChromeを使って確認できます。

```sh
node scripts/check-ui.mjs
node scripts/check-workflow.mjs
node scripts/check-ocr.mjs
node scripts/check-catalog.mjs
```

- `check-ui`：手入力、保存復元、アイコン選択・検索、グラフ切り替え、削除、モバイル表示。
- `check-workflow`：実画像の確認・修正・保存、名前補正、再登録防止、攻撃除外、編集、バックアップ復元、中止操作。
- `check-ocr`：提供された5枚を読み取り、結果とスクリーンショットを`.runtime/`へ出力。
- `check-catalog`：実際のGoogleスプレッドシートからの更新。外部通信が必要。

確認には独立したブラウザープロファイルを使い、普段の記録には触れません。
